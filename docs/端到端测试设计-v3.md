# 端到端测试设计 - v3

目的
- 验证店-代理-合伙人三位一体的端到端流程在生产接近场景下的正确性、鲁棒性与审计可追溯性。
- 覆盖从下单、支付回调、分润到账、提现等全链路，包含单路径直推与多路径并发情景。

场景概览
- 场景A：店铺直接加盟（Store -> Direct reward to 店主路径）
- 场景B：多级分润穿透（Partner -> Agent -> Store）
- 场景C：并发下的幂等性测试（Direct/Indirect/Team 的并发路径）
- 场景D：跨订单并发（不同订单对同一接收者的幂等性测试）

数据准备与种子数据
- 使用现有 schema.sql 与 seed 逻辑，在测试 DB 中创建：Partner、Store、Agent、Store 间的带有 tree_path 的关系链。
- 设置策略参数：STORE_JOIN_FEE、STORE_REWARD_DIRECT、REWARD_INDIRECT、PARTNER_TEAM_MANAGEMENT、HEADQUARTER_SUPPORT_FEE 等。

用例设计概要
- End2End-Store-Direct:
  - 构建 Partner -> Store A / Store B 的链路
  - 以 B 下单支付店铺加盟费，验证 A 收到 DIRECT_STORE 9000 的分润日志、余额增加
- End2End-MultiPath:
  - Partner -> Agent -> Store A -> Store B；下单在 B
  - 验证 A 的直接奖励、L 的间推奖励、P 的团队津贴
- End2End-Concurrency:
  - 以同一订单发出多次并发回调，验证幂等性（仅写入一次）
- End2End-CrossOrder:
  - 两个不同订单在同一收款方的并发分润，确保两笔订单的幂等性互不干扰

实现骨架建议
- 使用 SpringBootTest + @Transactional 的集成测试模式
- 使用 MySQL 测试实例（CI 中已有 MySQL 服务）
- 使用 ProfitService 来驱动分润逻辑，直接通过订单数据触发分润分支
- 断言点包括：分润日志条目、余额变化、以及可选的对账单产出

后续落地计划
- 逐步实现每个场景的测试实现，并在 CI 中固定执行所有端到端用例。
- 集成测试与端到端测试可共用数据准备工具，减少重复数据创建。
