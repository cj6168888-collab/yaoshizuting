# 端到端测试设计（End-to-End Test Plan）

项目：药师祖庭数字化系统
版本：1.0

目标
- 验证“店-代理-合伙人”三位一体的核心业务流程在端到端场景下的正确性、鲁棒性与审计可追溯性。
- 覆盖从下单、支付回调、分润到账、提现等全链路场景，确保数据一致性与幂等性。

范围与边界
- 包含最小路径场景（店铺加盟直接分润）以及包含边界条件的多级分润场景。
- 覆盖异常路径（重复支付回调、余额不足、权限不足等）的端到端验证。

测试用例总览
- 用例 T-01: 店主直接加盟并分润到店主账户（直推场景）
- 用例 T-02: 代理加盟包含直推奖励、间推奖励与总部扣费的多步分润
- 用例 T-03: 合伙人招募代理在达到阈值后的分润扣费（总部扣费）
- 用例 T-04: 多级分润穿透（合伙人 -> 代理 -> 店主 -> 新店主）
- 用例 T-05: 幂等性测试（重复支付回调不会重复发放）
- 用例 T-06: 账户余额不足时的失败路径与请求重试

数据准备
- 通过 policy_config 向系统注入关键参数：加盟费、分润金额、扣费金额等。
- 通过 gyt_user_hierarchy 树状结构路径路径路径，构造多级关系。
- 通过 order 表创建模拟的支付订单，设置 PAID 状态。
- 通过 profit_log 表核对分润日志的落地情况。

执行步骤
1. 环境准备
   - 通过 CI 或本地搭建 MySQL 测试实例，执行 schema.sql 初始化结构。 
   - 启动应用，确保申请了测试配置(application-test.yml) 的数据源。
2. 用例执行
   - 按顺序执行用例，记录关键输入/输出。
3. 验证点
   - 分润日志：确保每条分润的数量、类型、接收者、贡献者、订单号一致且幂等。
   - 余额变化：对应账户余额正确增加/减少。
   - 审计信息：确保日志可追溯（orderSn、receiverId、contributorId、createTime）。
4. 清理
   - 测试完成后清理数据库测试数据，确保环境可重复使用。
