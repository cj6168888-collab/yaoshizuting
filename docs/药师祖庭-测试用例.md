# 药师祖庭系统核心分润逻辑测试用例

**项目阶段**：逻辑验证与财务审计  
**核心目标**：覆盖所有身份组合，确保每一分钱的流向符合政策

---

## 一、店铺加盟场景（基础分润测试）

### 用例 101：店主 A 推荐新店主 B

- **前置条件**：A 角色为 STORE
- **操作**：B 支付 13,960 元加盟费
- **预期结果**：
  1. 直推奖：若 B 是 A 直推的第 1 家店铺，A 不获得直推奖励；从第 2 家起，按后台配置发放直推奖励，默认 9,000 元
  2. 间推奖：默认不发放；如后台启用间推奖励，需同时检查单笔最高分润是否超过加盟费
  3. 管理津贴：若 A 的上级有合伙人 P，且 B 是 P 团队后台配置范围内的店铺，P 获得后台配置的团队管理津贴，默认第 2-100 家每家 998 元
  4. 库存分配：B 账户自动生成 1 台仪器、20 套盒

### 用例 102：代理 L 推荐新店主 B

- **前置条件**：L 角色为 AGENT
- **操作**：B 支付 13,960 元
- **预期结果**：
  1. 直推奖：若 B 是 L 直推的第 1 家店铺，L 不获得直推奖励；从第 2 家起，按后台配置发放直推奖励，默认 9,000 元
  2. 团队收益：向上追溯合伙人，按后台配置范围发放团队管理津贴

## 二、代理/合伙人升级场景（高额分润测试）

### 用例 201：合伙人 P 招募第 1-10 名代理 D

- **前置条件**：P 角色为 PARTNER，agent_count < 10
- **操作**：D 支付 39,800 元
- **预期结果**：
  1. 管理培训费：P 账户增加 39,800 元
  2. 总部扣费：不触发 9,800 元扣款
  3. 计数器：P 的 agent_count 累加 1

### 用例 202：合伙人 P 招募第 11 名代理 D (边界值测试)

- **前置条件**：P 的 agent_count 已达到 10
- **操作**：D 支付 39,800 元
- **预期结果**：
  1. 管理培训费：P 账户增加 39,800 元
  2. 总部支持费：自动扣除 P 账户 9,800 元
  3. 最终净收益：P 本单净得 30,000 元

## 三、混合层级与策略风险测试（复杂链路）

### 用例 301：多级链路默认不发间推

- **层级关系**：合伙人 P -> 代理 L -> 店主 A -> 新店主 B
- **操作**：A 推荐第 1 家新店主 B 支付 13,960 元
- **预期结果**：
  - A (直推店主)：第 1 家不发放直推奖励
  - L (间推上级)：默认不发放间推奖励
  - P (团队津贴)：第 1 家不发放团队管理津贴；从后台配置的起始店铺数开始发放

### 用例 302：后台策略超额预警

- **层级关系**：合伙人 P -> 代理 L -> 店主 A -> 新店主 B
- **操作**：管理员在后台调整直推、间推、团队管理津贴等策略
- **预期结果**：
  - 后台允许保存配置，便于经营策略自由调整
  - 当单笔最高分润合计超过对应加盟费时，系统配置页和配置 API 返回风险提示
- **逻辑校验**：系统不静默接受明显亏损策略，必须向管理员展示超额警告

## 四、异常与安全测试

| 用例 ID | 场景描述 | 预期防御行为 |
|---------|----------|--------------|
| ERR_01 | 同一个支付回调信号被发送了两次（并发） | 系统利用 UNIQUE KEY 拦截，第二笔分润失败，余额不重复增加 |
| ERR_02 | 余额不足 39.8 元时尝试"0元补货" | 系统拦截下单，提示"账户余额不足，请充值服务费" |
| ERR_03 | 非合伙人角色尝试调用"招募代理"接口 | 系统返回 403 Forbidden，权限不足 |
